Journey Parameters

Scoring Method

Different normalization methods emphasize different aspects of the distribution:

Percentile Rank: Ranks areas 0-1 based on position in distribution. Linear relationship.

Log Transform: Compresses high values, spreads out low values. Reduces impact of outliers.

Sigmoid: S-curve emphasizing middle differences, compressing extremes. Smooth transitions.

Balanced: Multiplies percentiles instead of adding. Heavily penalizes having any low scores - rewards well-rounded accessibility.

How do weights work with each scoring method?

Additive methods (Percentile, Log, Sigmoid): - Weights act as multipliers: score = (jobs × weight) + (open_space × weight) + ... - Weight of 2 = count this amenity twice as much - Weight of 0 = ignore this amenity completely - Total score is a weighted sum

Multiplicative method (Balanced): - Weights act as exponents: score = (jobs ^ weight) × (open_space ^ weight) × ... - Weight of 2 = square the normalized value (much more dramatic effect) - Weight of 0 = exclude from the product (treated as 1) - A single low score in any weighted category heavily penalizes the total - Rewards mesh blocks that perform well across all selected amenities

Key difference: In multiplicative mode, weights have exponentially stronger effects. Use lower weights (0.5-1.5) for more subtle emphasis.

Methodology

This accessibility index adapts London’s Public Transport Accessibility Level (PTAL) methodology to Greater Melbourne, combining public transport routing with multi-amenity access analysis. Unlike simple distance-based measures, this approach models realistic journey times including walking, waiting, transfers, and temporal constraints.

Walking Network Foundation

The foundation of accessibility measurement begins with pre-computed walking isochrones from the VicMap road network. Using road infrastructure centroids as nodes and road segments as edges, we calculate walking distances from every point in the network using Dijkstra’s algorithm at a walking speed of 84 meters per minute (5 km/h). These isochrones extend up to 20 minutes and are processed in parallel.

Transit Network Integration

Public transport data comes from GTFS (General Transit Feed Specification) schedules for Melbourne’s rail, tram, and bus networks. The analysis filters services to a specific day type (weekday/weekend) and time window to model typical commuting patterns. Each transit stop is linked to the nearest road infrastructure node, creating a bridge between the walking network and transit services.

Time-Expanded Graph Routing

The core innovation is a time-expanded graph where vertices represent (stop, remaining_time) pairs rather than simple locations. When routing from a mesh block centroid:

  1. Walking time to the nearest transit stop is deducted from the total time budget
  2. From each stop, we identify which other stops are walkable and which transit services depart within the feasible time window
  3. Time margins ensure passengers have sufficient walking time between stops before scheduled departures
  4. Temporal dominance pruning skips vertices if a stop has already been visited with more remaining time
  5. The algorithm returns all mesh blocks reachable within the total journey time limit (currently 46 minutes from an 8:59 AM departure)

This approach models real-world constraints: you cannot “double back” in time, and transfers require both walking feasibility and schedule compatibility.

Amenity Data Aggregation

Multiple amenity types are aggregated at the mesh block level through spatial intersection:

  • Employment: Proportionally allocated from ABS Destination Zones based on spatial overlap
  • Open Space: Derived from OpenStreetMap leisure features (parks, nature reserves, gardens)
  • Supermarkets: OSM retail tags (supermarket, greengrocer, grocery)
  • Community Facilities: VicMap Features of Interest including sport centers, schools, childcare, tertiary institutions, hospitals, and health facilities

Each reachable mesh block contributes its amenity counts to the origin’s accessibility score.

Accessibility Scoring

Raw accessibility scores sum all amenities reachable within the time budget, weighted by user-defined preferences. The interactive controls above allow real-time re-weighting to explore different accessibility priorities—emphasizing employment access versus education, health services, or recreational amenities.

Final scores are percentile-ranked (0-1 scale) to enable comparison across amenity types with different magnitude ranges. The total accessibility index sums these percentile ranks, creating a composite measure of multi-amenity access quality.
